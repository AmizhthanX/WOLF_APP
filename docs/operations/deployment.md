# Deploying WOLF to Google Cloud

WOLF runs on **one small VM** in Mumbai (`asia-south1`): chosen for a free-trial deployment that can be switched
off without losing the design. The owner's steps are in the [owner guide, Part 8](../development/owner-guide.md);
this page is how it works.

```
                  Cloudflare DNS (DNS only)
   amizhthan.app  api.  relay.  turn.   ──►  static IP
                                              │
  ┌─────────────────────── VM "wolf" (e2-small, Debian 13) ───────────────────────┐
  │  Caddy :80 :443 ── amizhthan.app ──► web       (Next.js standalone)           │
  │                 ── api.          ──► api       (services/api)                 │
  │                 ── relay.        ──► realtime  (services/realtime, WebSockets)│
  │  coturn :3478 udp/tcp, relay 49160–49200/udp   (host network)                 │
  │  postgres  (volume on the boot disk; nightly disk snapshot, kept 7 days)      │
  └───────────────────────────────────────────────────────────────────────────────┘
       ▲ images: Artifact Registry          ▲ secrets: Secret Manager
```

## Pieces

| Path | What it is |
| --- | --- |
| `infrastructure/terraform` | Network, firewall, static IP, VM, service account, Artifact Registry, empty secrets, snapshot schedule |
| `infrastructure/gcp/startup.sh` | Runs at boot and on every deploy: installs Docker, reads secrets into `/run/wolf` (memory), starts compose |
| `infrastructure/docker/compose.yml` | The six services, their isolation, and their start order (migrations before API and relay) |
| `infrastructure/docker/*.Dockerfile` | The server image (API and relay, one image) and the dashboard image |
| `infrastructure/docker/compose.local.yml` | The same images on a developer PC, without Caddy or TURN |
| `scripts/deploy-gcp.mjs` | `secrets`, `deploy`, `status`, `local-secrets` |

## Security decisions

- **Only Caddy and TURN face the internet.** The API, relay, dashboard and database listen on a private Docker
  network. Caddy replaces any client-supplied `X-Forwarded-For`, which is what the rate limiters read.
- **SSH only through Identity-Aware Proxy.** WOLF has its own VPC, not the default one whose rules open SSH and
  RDP to everyone. Port 22 accepts only Google's IAP range; OS Login ties access to IAM.
- **Secrets never touch Terraform state, a file in the repository, or the VM's disk.** Terraform creates empty
  secrets. `deploy-gcp.mjs secrets` generates each value on the owner's PC and hands it to `gcloud` on standard
  input. The VM reads them with its own service account — allowed to read exactly these secrets and pull exactly
  this repository — into `/run/wolf`, a memory filesystem, readable by root, and by the one container user each
  file is for.
- **An existing secret is never regenerated by the script.** A new database password would lock WOLF out of its
  own database; a new token secret signs everyone out; a new webhook key makes every stored webhook unreadable.
  Rotation is a deliberate, manual act.
- **TURN relays to the public internet only.** coturn refuses every private, loopback, link-local, CGNAT and
  documentation range, so a TURN credential cannot reach the VM's own services or Google's internal network.
  Credentials are the short-lived HMAC ones the API already mints.
- **Containers run read-only, with every capability dropped** and `no-new-privileges`, as unprivileged users.
- **Health endpoints are not public.** Caddy answers `/healthz` with 404: the relay's counts connected PCs.
- **The owner account is made on the VM** by `/opt/wolf/create-owner.sh`, which reads the password hidden and
  passes it only as a container's environment — never on a command line or into shell history.

## Deploying a change

```powershell
node scripts/deploy-gcp.mjs deploy
```

Builds both images tagged with the commit, pushes them, sets the VM's `wolf-image-tag` metadata, and runs the
startup script again over IAP SSH. Compose recreates only what changed. A deploy refuses uncommitted changes, so
every running image names the commit it came from.

**Rollback:** set the tag back and run the startup script:

```powershell
gcloud compute instances add-metadata wolf --zone=asia-south1-a --metadata=wolf-image-tag=<previous tag>
gcloud compute ssh wolf --zone=asia-south1-a --tunnel-through-iap --command="sudo google_metadata_script_runner startup"
```

Artifact Registry keeps the five most recent images. A migration is never rolled back automatically; migrations
are additive so an older image runs against a newer schema.

## Looking at it

```powershell
node scripts/deploy-gcp.mjs status
gcloud compute ssh wolf --zone=asia-south1-a --tunnel-through-iap
```

On the VM: `cd /opt/wolf && sudo docker compose logs --tail=100 api` (or `realtime`, `web`, `caddy`, `turn`,
`db`). Logs are rotated on the VM (5 × 10 MB per service) and hold metadata only, as everywhere in WOLF.

## Backups and restore

The boot disk, which holds the database volume, is snapshotted every night at 20:00 UTC and kept for seven days.
To restore: create a disk from a snapshot, stop the VM, swap the boot disk, start it. Secrets are in Secret
Manager, not on the disk, so a restored disk starts with the current ones.

## Stopping it

- **Pause** (keeps everything, stops compute charges): `gcloud compute instances stop wolf --zone=asia-south1-a`.
  The static IP and disk still cost a little.
- **Remove everything**: `terraform destroy` in `infrastructure/terraform`. Snapshots are kept
  (`KEEP_AUTO_SNAPSHOTS`) until deleted by hand.
- **When a free trial ends** Google stops the project's resources by itself; nothing is charged unless the owner
  upgrades the billing account.

## Moving to managed services later

The images do not change. Cloud Run takes the dashboard and API images, Cloud SQL replaces the `db` container
(`DATABASE_URL`, `DATABASE_SSL=require`), and the realtime relay and coturn stay on a VM: the relay holds
long-lived WebSockets and an in-memory registry of connected PCs, and TURN needs UDP.

## Known limits

- One VM: a VM failure stops WOLF until it restarts (Compute Engine restarts it on host failure).
- TURN over TLS (`turns:` on 443) is not offered, so a network that blocks UDP and port 3478 cannot relay.
- The first certificate needs the four DNS records to point at the static IP, and Cloudflare's proxy **off**.
